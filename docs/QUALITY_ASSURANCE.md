# Cosmo-riders — Quality Assurance

## Назначение

Система проверяет исходный код, межмодульные ссылки, тесты, production-артефакты и опубликованные ресурсы. Она не заменяет ручную проверку реального WebGL-рендеринга. Workflow ограничен веткой `test`; pull request проверяется без публикации.

## Команды

| Команда | Назначение |
|---|---|
| `npm test` | Регрессионные тесты физики, рендеринга, процедурных поверхностей и форматирования. |
| `npm run audit:static` | Проектные архитектурные инварианты из `scripts/audit.ts`. |
| `npm run audit:types` | Проверка TypeScript через `tsc --noEmit`. |
| `npm run audit:imports` | Локальные импорты, динамические импорты, URL Worker, существование файлов, регистр путей и циклические зависимости. |
| `npm run audit:assets` | Локальные ссылки `src`, `href`, `poster` и CSS `url()` в HTML/CSS с учётом каталога `public/`. |
| `npm run audit:build` | Production-сборка Vite и проверка сгенерированных entry points. |
| `npm run audit:deployment` | Проверка `dist/`, JS/CSS ссылок, отсутствия исходных TS-файлов и наличия `.nojekyll`. |
| `npm run audit:live` | HTTP-проверка опубликованных страниц и MIME-типов JS/CSS. Запускается после deployment. |
| `npm run audit` / `npm run audit:all` | Последовательно запускают тесты, статические проверки, TypeScript, импорты, ресурсы, production-сборку и аудит артефактов. |
| `npm run check` | Совместимый алиас полного аудита. |

Требуется Node.js 20 или новее.

## Уровни проверки

### Static Audit
Проверяет существующие DOM-контракты, структуру рендерера, процедурную геологию, Worker-transfer, SI-константы, отдельные физические и графические инварианты, синтаксис runtime JavaScript и ссылки на модули. Часть архитектурных проверок намеренно привязана к существующим контрактам и должна обновляться вместе с осознанным изменением архитектуры.

### Type и Build Audit
TypeScript компилируется без генерации файлов. Vite собирает обе страницы — корневую и `/lab/`. Проверяется, что HTML ссылается на скомпилированные JS/CSS, файлы существуют, а исходные TypeScript-модули не попали в публикацию.

### Integration и Regression
Текущий Node test suite проверяет детерминированную физику, процедурную генерацию, LOD и графические контракты. Это не браузерные end-to-end тесты и не проверка реального WebGL-контекста.

### Deployment Audit
Единый Pages workflow запускает полный `npm run audit` до загрузки артефакта. Pull request не публикуется. Push в `test` и ручной запуск публикуют только после успешной сборки. После публикации отдельный smoke test запрашивает обе страницы и проверяет MIME JS/CSS.

## Ручная проверка браузера

После изменений UI, шейдеров, камеры, LOD или ресурсов необходимо:

1. Открыть опубликованные `/` и `/lab/`, включая прямую перезагрузку каждой страницы.
2. Проверить DevTools Console и Network: исключения, 404, MIME errors и неуспешные запросы.
3. Проверить создание WebGL2-контекста и fallback при его отсутствии.
4. Переключать фокус между Солнцем, планетами и спутниками; убедиться, что сцена остаётся общей.
5. Проверить вращение, панорамирование, масштабирование и переходы LOD.
6. Переключить атмосферу, облака, тени, HDR и пресеты; проверить ошибки компиляции/линковки шейдеров.
7. Наблюдать frame time и память при многократных переключениях фокуса и приближении. Записывать браузер, оборудование, сцену и метод измерения.

CI PASS не доказывает визуальную корректность, отсутствие утечек памяти или высокую частоту кадров.

## Расширение аудита

Для новой подсистемы добавлять детерминированные тесты чистой логики, integration-проверки контрактов, проверки ресурсов и шейдеров. Для функций, зависящих от браузера или GPU, указывать ручной сценарий либо добавлять реальный browser test. Не ослаблять проверку только ради зелёного CI.

## Статусы

- **PASS** — проверка завершилась успешно.
- **FAIL** — обнаружено нарушение.
- **BLOCKED** — внешняя среда не позволила выполнить проверку.
- **NOT RUN** — проверка не запускалась.

Live smoke test выполняется после публикации: он может завершиться ошибкой уже после того, как артефакт был опубликован.
