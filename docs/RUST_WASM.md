# Rust and WebAssembly

## Build

The workspace is rooted at Cargo.toml; the cosmo-core crate builds as both rlib and cdylib. The browser package is generated by wasm-pack with target web and output directory src/wasm/pkg.

The generated src/wasm/pkg directory is a build output and is not hand-maintained. Vite bundles its JavaScript glue and emits the WASM binary as a deployable asset.

## Worker boundary

src/rendering/geodesic/surface-tile-worker.ts initializes wasm-bindgen once before sending its ready handshake. The existing bounded SurfaceTileWorkerPool dispatches tile and mesh tasks to that worker. A worker failure remains a worker failure and is surfaced through the existing error path; it does not silently fall back to expensive synchronous generation on the main thread.

The worker transfers generated channel and mesh ArrayBuffers back to the caller. Rust creates owned JS typed arrays for the returned payload, so TypeScript never stores a view into WASM memory that could be invalidated by memory growth.

## Exported API

- propagate_kepler: universal-variable two-body propagation; input and output vectors use f64.
- generate_surface_tile: deterministic geodesic page generation from a compact profile JSON string; returns typed arrays for five channels.
- build_geodesic_tile_mesh: creates the triangular geodesic mesh and index buffer.

The surface/mesh functions are called from the geodesic worker. The propagation export is available for the physics bridge but the active PhysicsWorld has not yet been switched to an asynchronous WASM snapshot API.

## Memory and threading

No SharedArrayBuffer, atomics or WASM threads are required. One worker is used by the current surface worker pool. The task queue remains bounded to avoid overwhelming the four-thread i5-4670K system. Large output buffers are transferred, not copied again by postMessage.


## Additional computational exports

- `build_geodesic_stitch_indices(resolution, coarseEdgeMask)` creates a conforming triangular index buffer for the three coarse-neighbor edges. The edge mask uses AB=1, BC=2 and CA=4. It is exposed through WASM as a `Uint32Array`.
- `gravitational_acceleration(position, mu)` returns the point-mass acceleration in m/s² using f64 inputs and output.
- `specific_orbital_energy(position, velocity, mu)` returns specific orbital energy in J/kg.

These exports extend the Rust computational API. They do not yet replace the active TypeScript LOD balancer or the full PhysicsWorld; those integrations remain separate migration work.
